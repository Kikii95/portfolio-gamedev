  ## Concept

  Trois agents Claude collaborent pour bootstrapper un projet complet :

  ```
  ┌──────────────┐
  │ PromptAgent  │  Dialogue avec l'utilisateur
  │  (dialogue)  │  → specs, bootstrap, prompts
  └──────┬───────┘
         │  mao run
         ▼
  ┌──────────────┐       ┌──────────────┐
  │  ChefAgent   │ ────▶ │ WorkerAgent  │
  │ (planifie)   │ ◀──── │ (exécute)    │
  └──────────────┘       └──────────────┘
                          Claude Code CLI → code réel sur disque
  ```

  Workflow : `mao init` → conversation → `mao run` → projet bootstrappé.

  ## Abonnement plutôt qu'API

  Le provider principal appelle **Claude Code CLI en subprocess** (`claude --print --output-format=json`) au lieu de l'API Anthropic. MAO consomme l'abonnement Claude Code ; le JSON renvoyé sert à suivre tokens et coût estimé par run. Le provider API direct reste un stub.

  ## Memory system

  MAO capture ce qu'il apprend pendant l'exécution, en cinq types : PATTERN, LEARNING, DECISION, ERROR, SUCCESS.

  - Retrieval sans embeddings : somme pondérée de correspondance de tags, recouvrement de mots-clés, confiance et récence (décroissance exponentielle, demi-vie 30 jours)
  - Injection markdown dans les system prompts, avec un budget de caractères
  - Depuis la v1.2 : pool de mémoire global partagé entre projets

  ## Exécution hiérarchique

  Pour les gros projets, un **ArchitectAgent** découpe en sous-systèmes avant de déléguer aux Chef/Workers. Coordination via un message bus interne. Workers spécialisés (backend, frontend, test, devops) routés par capability tags. Effort réglable par tâche (`low` → `max`).

  ## Completeness Gate

  Un run n'est déclaré terminé qu'après une série de vérifications enregistrées (dont un smoke test des scripts du projet). Depuis juillet 2026, la comptabilité des rejets tient compte de la progression, et une option permet de clore avec réserves quand le gate est épuisé.

  ## Web UI

  Sept pages React (Vite + composants shadcn/ui + Zustand + Tailwind 4) :

  - **Prompt** - chat avec PromptAgent + liste des projets
  - **Dashboard** - vue cross-projet : statuts, runs sur 30 jours, mémoire par type
  - **Settings** - configuration Chef/Worker
  - **Approvals** - file de sécurité + audit log
  - **Split View** - Chef ↔ Worker en temps réel via WebSocket (NarratorAgent, timers, effort)
  - **Stats** - timeline, fichiers et langages produits
  - **Memory** - CRUD des entrées, aperçu du retrieval

  ## Module Security

  - **Modes** : `autonomous` (défaut, checks désactivés) ou `strict` (checks actifs, commandes risquées bloquées ou soumises à approbation)
  - **Auto-whitelist** en `strict` : scripts dev détectés (package.json, Makefile, pyproject.toml)
  - **Audit log JSONL**

  ## Overnight mode

  Pour les runs de plusieurs heures : backend uvicorn en `tmux` détaché, checkpoint atomique (temp + swap) par run, reprise d'un run `interrupted` depuis l'UI, pause/resume manuels.

# MAO - Multi-Agent Orchestrator

Framework qui fait collaborer plusieurs agents Claude pour générer des projets entiers sans micro-management.

## Contexte

Projet personnel démarré le 03/02/2026. Premières versions (0.1 → 0.4) le jour même, memory system en v0.5.0 (24/04), dashboard cross-projet et historique des runs en v0.8.0 (25/04), v1.2.0 le 01/05 avec la mémoire partagée entre projets. Le Completeness Gate a été retravaillé en juillet 2026.

Claude Code seul fait du bon travail, mais sur des tâches longues il faut le relancer sans arrêt. MAO automatise cette boucle : un agent clarifie le besoin, un autre planifie, un troisième exécute.

## Fonctionnalités

**Abonnement plutôt qu'API** - Le worker passe par Claude Code CLI en subprocess : MAO consomme l'abonnement, pas des tokens API facturés à l'unité.

**Memory system** - MAO note patterns, erreurs et succès, puis les réinjecte dans les prompts des runs suivants, y compris d'un projet à l'autre.

**Completeness Gate** - Un run ne se termine qu'une fois les vérifications passées.

**Overnight mode** - `tmux` détaché, checkpoint atomique, reprise après interruption.

**Web UI temps réel** - Split view Chef/Worker via WebSocket, dashboard cross-projet, file d'approbation sécurité.
